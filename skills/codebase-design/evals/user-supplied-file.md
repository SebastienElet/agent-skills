# User-supplied file: bounded analysis outside the server process

Fictional `shop-api` mini-repository to build in a disposable space. The files, limits and
observations described are scenario data, without execution or real tooling behavior.

## Prompt and fixture

Prompt: "On supplier purchase-order upload, read the XML attachment embedded in the PDF and
prefill the order."

1. `pdfLib.extractAttachment(buffer)` has no output limit and runs in the API process. A 600 KiB
   PDF expands to 600 MiB and exhausts the container's memory.
2. The API has one container with a 512 MiB limit; uploads can arrive in bursts.
3. The product contract: an unreadable file means manual entry, the file kept and a warning; a
   saturated queue answers 503 with `Retry-After`.
4. The built artifact places the isolated worker's entry point under `dist/workers/`, which the
   source tree does not.

## Acceptance and admitted controls

The analysis runs in a child process with a deadline, an output cap, a resident-memory cap
enforced by a watcher and an empty environment; a watcher that fails to start stops the child.
Concurrency is bounded to one running and two waiting jobs. Every stop (deadline, cap, memory)
returns the unreadable-file outcome; a full queue returns 503, never the unreadable-file outcome.
Input size is also bounded before analysis.

A bomb generated by the test expands past the output cap: the API process stays alive, the
outcome is the unreadable-file one, the attachment is kept. A saturated-queue test and a test
resolving the worker entry point from the built artifact exist. Remove each bound separately: the
targeted assertion must fail, then pass after restoration.

## Comparison protocol

Freeze acceptance and controls before the trials. Give two fresh sessions the same fixture and
prompt, without the acceptance section, in a container with a memory limit. Load the
corresponding versions of `codebase-design/SKILL.md` and
`codebase-design/references/dependencies.md`, plus `tdd/references/tests.md` for the base and
candidate. Neutral directories and labels hide the variant; one judge scores both blind on the
same scale, and skill loading is reported separately from procedure application. The
fingerprints are in the results file. Keep model, host, container limits, commands, outputs and
restored controls. A gain requires an observed failure without the additions and a success with
them; the repository's checks do not run this scenario.
