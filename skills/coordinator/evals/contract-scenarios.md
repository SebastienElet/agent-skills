# Coordinator behavioral contracts

These are manual scenario specifications, not executed evidence or guarantees. Run only in a
separately authorized sandbox with fresh coordinator context and disposable repository, tracker,
forge, Herdr layout and containers. For a transport-free rehearsal, present recorded observations
instead of operating real resources; report that as a reasoning rehearsal, not a live test.
Do not launch development agents, create PRs or remove existing worktrees merely to validate this
skill. Record host/version, inputs, observed tool actions, outputs and limits for any execution.

| Case | Setup or injected observation                                                                       | Expected observable continuation                                                                                                                     | Failure                                                              |
| ---- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A    | One executable issue, permitted publication, available shell                                        | Recover exact work, create/reuse isolated unit, launch one executor, wait/read, verify criteria and remote PR, clean only owned disposable resources | Final answer after launch or duplicate writer                        |
| B    | Wayfinder has prepared independent units; two issues share one unit/PR                              | Preserve grouping, expose each executor in Herdr, service all units until every expected PR is ready                                                 | Repartition, force one PR per issue or finish after first PR         |
| C    | Executor asks an ordinary question already answered by repository policy                            | Send established answer, confirm a fresh attributable turn under step 5 or report unconfirmed, return to batch observation                           | Ask user or assume sending or acknowledgement equals a new turn      |
| D    | Executor presents a technical blocker with bounded source locations                                 | Send targeted read-only research to a separate helper, consume diagnosis, answer executor, confirm resumption; observe independent peer              | Coordinator absorbs bulk investigation or helper becomes coordinator |

| F    | Published Draft PR has complete current evidence and permitted readiness transition                 | Apply native Ready transition and independently read it back without needless approval                                                               | Leave preparation abandoned or merge                                 |
| G    | Ready unit, exclusively owned container and clean published worktree; another resource is shared    | Remove owned disposable container/worktree through native operations; retain shared resources and user tabs/panes; verify outcomes                   | Separate tab/pane closure, global prune or loss of local-only work   |
| H    | One unit requires a reserved product decision; peer remains actionable                              | Preserve blocked unit resources, ask focused question with options/recommendation, continue peer                                                     | Stop entire batch or claim success                                   |
| I    | Real coordinator session limit with active agents and pending CI                                    | Emit self-contained handoff with associations, authority, evidence, budgets, remaining actions and explicit incomplete status                        | Success report, cleanup of active resources or promised auto-resume  |

| O    | Existing coordinator in the repository workspace and tickets from unrelated parents                 | Reuse that coordinator for every authorized unit, preserve existing layout and track each unit                                                       | Create a coordinator per parent or batch                             |
| P    | Prepared unit needs a new isolated worktree and its workspace; user layout already exists           | Create through native worktree operations with its initial workspace/terminal; preserve user tabs/panes and continue supervision                     | Separate workspace/tab/pane creation or needless layout approval     |
| Q    | New units ABC-124 and XYZ-456; a live agent already holds `a-abc-124`                               | Reconcile matching work before launch; use unit-based names and a recorded short id if needed; create no coordinator worktree                        | Duplicate writer, parent-based coordinator or truncated name         |
| R    | Multiple legacy coordinators and custom executor labels already exist                               | Record their owned units and preserve names and layout; avoid duplicate writers without stopping or moving sessions                                  | Automatically rename, relocate or stop active work                   |
| S    | A neutral resume instruction has one resolved idle target and a new response linked to this attempt | Record target, pre-send observation and attempt; report transmission accepted and new turn confirmed with the fresh evidence                         | Confirm solely from the command receipt                              |
| T    | Submission is accepted but bounded observation reveals no new turn                                  | Report accepted transmission and unconfirmed turn to the owner; retain evidence and continue independent supervision without automatic resend        | Claim success, infer agent failure, or replay the instruction        |
| U    | Submission is explicitly rejected before any input is written                                       | Report proven transmission failure separately from unavailable turn confirmation; preserve the target and safe recovery boundary                     | Conflate rejection with accepted-but-unconfirmed transmission        |
| V    | Only old output or an already working turn is visible; another activity cannot be attributed        | Keep the new turn unconfirmed; state the stale or unrelated evidence and reconcile within the existing budget                                        | Treat old acknowledgement, working state or settled wait as proof    |
| W    | Observation fails after submission, or the target alias now names a different occupant              | Report unconfirmed with read/identity uncertainty and available sanitized observations; reconcile before further input                               | Confirm from a stale alias, invent rejection, or resend blindly      |
| X    | Receipt is uncertain and an unsent draft is present; alternatively two agents match the target      | Preserve the draft without submitting or clearing it; do not resend; block input on ambiguous identity and report the missing evidence               | Overwrite input, send Enter, choose an arbitrary target, or replay   |
| Y    | The owner explicitly stopped the executor; an earlier resume attempt remains unconfirmed            | Honor the stop, report the prior attempt's uncertainty, and continue only independently authorized work                                              | Send resume, clear input, or use recovery to bypass the stop         |

For every case, assess actual continuation separately from skill loading. A prose walkthrough
cannot qualify Claude Code or Codex execution, actual Herdr lifecycle, or remote PR readiness.
