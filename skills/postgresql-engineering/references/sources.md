The verification baseline is PostgreSQL 18; runtime fixtures must report the actual minor and
platform. Versioned manuals can receive corrections and are not immutable commit snapshots.
For another major, reread the corresponding manual and release notes, then execute the affected
cases. This is not certification of every PostgreSQL version or client. PostgreSQL 15+ NULLS NOT
DISTINCT is explicitly version-gated; other version-sensitive options require target discovery.

## Recommendations conditioned or excluded

| Upstream candidate                                                                                    | Decision and official basis                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Always start real diagnostics with EXPLAIN ANALYZE                                                    | Rejected: execution and effects need authority. Start with observations/EXPLAIN; [EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html) documents execution and rollback limitations                      |
| Composite indexes outperform separate indexes by a fixed factor; trailing-key queries cannot use them | Rejected: workload and cost determine choice; [multicolumn indexes](https://www.postgresql.org/docs/18/indexes-multicolumn.html) includes version-sensitive skip scan                                             |
| INCLUDE eliminates heap access                                                                        | Conditioned on visibility and planner choice; [index-only scans](https://www.postgresql.org/docs/18/indexes-index-only-scans.html) still need heap checks when all-visible bits are unset                         |
| Keyset pagination is always constant-time                                                             | Rejected: selectivity, ordering, index and workload matter; preserve a complete cursor and define snapshot behavior; [LIMIT](https://www.postgresql.org/docs/18/queries-limit.html) requires predictable ordering |
| LATERAL is intrinsically faster than windows                                                          | Rejected: select by cardinality/preservation first and measure; [table expressions](https://www.postgresql.org/docs/18/queries-table-expressions.html) defines its semantics                                      |
| UPSERT eliminates application races; MERGE can replace it                                             | Narrowed to the documented arbiter outcome, with empty RETURNING and snapshot races; [isolation](https://www.postgresql.org/docs/18/transaction-iso.html) distinguishes these commands                            |
| One multi-row UPDATE acquires all locks in a universally safe order                                   | Rejected as a deadlock guarantee; inspect all resources/paths and handle deadlocks; [locking](https://www.postgresql.org/docs/18/explicit-locking.html)                                                           |
| Seq Scan, high reads or a disk sort directly imply an index or memory setting                         | Rejected: examine estimates, distribution, cache, waits and resource budget; [plan interpretation](https://www.postgresql.org/docs/18/using-explain.html)                                                         |
| Fixed vacuum/bloat thresholds, memory ratios or automatic indexing of every FK                        | Excluded as defaults; observe the workload and invariant; [VACUUM](https://www.postgresql.org/docs/18/routine-vacuuming.html), [constraints](https://www.postgresql.org/docs/18/ddl-constraints.html)             |
| One preferred type for all money, or JSONB for arbitrary relationships                                | Rejected: preserve canonical units, precision and relational invariants; [numeric types](https://www.postgresql.org/docs/18/datatype-numeric.html), [JSON](https://www.postgresql.org/docs/18/datatype-json.html) |

No numeric speedup or global impact priority from either guide is retained. Backup, replication,
major-version operations and specialized extension recipes are not imported. Existing development,
diagnosis and review skills continue to own their workflows; this skill adds PostgreSQL reasoning
without mandatory tool installation, an external activation router or a new delivery barrier.
