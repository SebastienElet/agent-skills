# Simplify an Issue or Draft

Read this only for explicit simplification, lightening or decluttering of an issue or draft. Apply
the common specification workflow at unchanged scope, returning a proposal only. Do not create,
edit, comment on, close, merge or otherwise mutate remote issues, even if the same request asks
for an update. Do not add a tracker client or publication mechanism.

## Analysis and proposal

1. Preserve the original problem, promised outcome, requirements, evidence and decision status.
   Read the complete available issue body and relevant comment decisions. Limit adjacent reads to
   overlap, dependencies or conflicting scope that could change interpretation; no backlog audit.
2. Before restructuring acceptance criteria or evidence, read
   `../../issue-workflow/references/completion-evidence.md` for evidence semantics only, not its
   mutation procedures. If unavailable, stop that restructuring and report the missing reference;
   continue independent wording work with criteria and proof unchanged.
3. Seek removal of unnecessary material before shortening sentences: repetition, session
   narration, speculative solutions, premature implementation sequences and options with no
   established need. Group related statements only when their conditions and evidence agree.
   Retain a justified technical constraint with its source; remove suggested means only when no
   established requirement depends on them.
4. Keep reductions, additions, splits, combinations and allegedly obsolete requirements in a
   separate scope proposal with rationale, impact and required decision. Moving deliverables
   between issues changes scope; regrouping equivalent prose does not.
5. Preserve useful data, relevant states and errors, permissions, compatibility, real dependencies,
   acceptance criteria and evidence links. Retain recorded environments and checked or unchecked
   status without claiming a rerun. Different evidence statuses stay separately identifiable.
   Never soften, delete, check or move unfinished criteria elsewhere to imply completion.
   Unavailable evidence is not disproof. Missing criteria remain a visible gap; suggestions are
   proposed, not new established requirements.
6. Present gaps or contradictions, the proposed title/body in the specialist or project structure,
   and a semantic diff naming what is kept, removed, grouped and awaiting decision. Trace each
   original requirement to the equivalent draft. State that no remote write occurred; return the
   proposal even when asked to create, update, close or merge remotely. Existing-issue editing is
   not an available `issue-creation` mode.
